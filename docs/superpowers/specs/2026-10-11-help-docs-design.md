# Справка в портале — дизайн

Макет: https://claude.ai/artifact/1ovZbC73sBfYZcsCi4Q9f1 (одобрен 11.10; файл — `.superpowers/sdd/2026-10-11-help-docs/mockup.html`).

## Зачем

Функций в портале много, а пользовательской документации нет: `docs/` — разработческие файлы, в интерфейсе только подсказки у полей. Нужна справка внутри портала для двух читателей — клиентов и сотрудников. В этой работе делается каркас: две страницы, набор разделов и способ добавлять статьи. Сами тексты владелец пишет постепенно, поэтому каркас обязан нормально выглядеть и при трёх статьях.

Решения владельца (11.10):
- вход — ссылка «Справка» в подвале, пункта в меню нет;
- статьи — Markdown-файлы в репозитории, приезжают с деплоем;
- сотрудник видит обе части, клиент — только свою и о второй не знает;
- только после входа;
- раздел показывает все свои статьи, сворачивания нет;
- пока в справке нет ни одной статьи, видимой читателю, ссылки в подвале нет; статей-образцов и черновиков не делаем.

## Что не входит

Редактор в портале, поиск по тексту статей, скрытие статей по правам, ссылки «?» со страниц портала на статьи, перевод на другие языки.

## Содержимое

Каталог `backend/help/` попадает в образ бэкенда (`COPY . .`) и виден в деве сразу (bind-mount).

```
backend/help/
  sections.js                      каталог разделов
  client/<раздел>/<статья>.md
  client/<раздел>/img/<файл>       картинки раздела
  staff/<раздел>/<статья>.md
```

**`sections.js`** — упорядоченный список: `{ audience: "client" | "staff", key, title, modules? }`. `modules` — ключи из `Preferences.modules`; раздел виден, если включён хотя бы один из перечисленных. Порядок в файле = порядок на странице.

**Статья** — файл с шапкой между строками `---`:

| Поле | Обязательно | Смысл |
|---|---|---|
| `title` | да | заголовок статьи и строка в оглавлении |
| `summary` | да | аннотация под заголовком; по ней ищет поиск |
| `order` | нет | место в разделе; без него — после упорядоченных, по алфавиту |
| `updated` | нет | дата `ГГГГ-ММ-ДД`, строка «Обновлено …» |
| `link`, `linkLabel` | нет | адрес в портале и подпись кнопки («Открыть уведомления»); задаются только парой |

Шапка — плоские пары `ключ: значение`, разбирается своим небольшим разборщиком (зависимость не добавляем). Адрес статьи — имя файла без `.md`: латиница, цифры, дефис. Файл с негодным именем или без `title`/`summary` в справку не попадает; в лог пишется предупреждение с путём.

Тело — обычный Markdown без своих расширений: `##` — заголовки для рейки, нумерованный список — шаги, цитата — заметка, полужирный — названия кнопок, картинка — относительным путём `img/файл.png`.

Название продукта в статьях не пишем («портал», а не имя бренда): инсталляции брендируются.

### Разделы

Клиентам: `start` Начало работы · `tickets` Заявки · `company` Компания и сотрудники · `devices` Устройства и рабочее место (`inventory`) · `reports` Отчёты и согласование работ (`timeTracking`, `finances`) · `knowledge` База знаний (`knowledgeBase`) · `account` Аккаунт и уведомления.

Сотрудникам: `start` Начало работы · `tickets` Заявки · `conversations` Диалоги (`messaging`) · `works` Работы и время (`timeTracking`) · `reports` Отчёты и согласование (`finances`) · `team` Команда · `companies` Компании и пользователи · `devices` Устройства (`inventory`) · `knowledge` База знаний (`knowledgeBase`) · `mikrotik` Мониторинг Mikrotik (`mikrotik`) · `notifications` Уведомления и Telegram · `admin` Администрирование.

## Бэкенд

Почему справка отдаётся бэкендом, а не вшивается в сборку фронтенда: сотрудническая часть не должна попадать в браузер клиента.

**`backend/services/help/`**
- `frontMatter.js` — чистая функция: текст файла → `{ meta, body }`.
- `catalogue.js` — читает `sections.js` и каталог статей, проверяет имена и шапки, строит индекс. В проде индекс строится один раз при первом обращении; вне прода — заново на каждый запрос, чтобы правка файла была видна сразу.
- `visibility.js` — чистые функции: какие аудитории открыты читателю (клиент → `client`; сотрудник → `staff`, `client`) и какие разделы видны при данном наборе модулей. Раздел без видимых статей отбрасывается.

**Маршруты** (`backend/routes/internal/help.js`, контроллер `backend/controllers/help.js`), все под `isAuth`:

- `GET /api/help` → `{ audiences: [{ key, sections: [{ key, title, articles: [{ slug, title, summary }] }] }] }` — только открытые читателю аудитории, только видимые разделы.
- `GET /api/help/:audience/:section/:slug` → `{ title, summary, updated, link, linkLabel, body, section: { key, title }, siblings: [{ slug, title }] }`. `body` отдаётся как в файле; относительные пути картинок на адреса маршрута ниже заменяет фронтенд (`util/help.js#resolveImages`): только он знает адрес API.
- `GET /api/me` дополняется полем `hasHelp`: есть ли у читателя хотя бы одна видимая статья.
- `GET /api/help/:audience/:section/img/:file` → файл картинки. Сессия приходит cookie, поэтому `<img>` работает без заголовков. Отдаём только растровые типы (png, jpg, webp, gif), `nosniff`.

Чужая аудитория, скрытый модулем раздел, неизвестная статья — всегда 404, без различия причин. Параметры пути проверяются тем же шаблоном имени, что и файлы, поэтому выход за каталог невозможен.

## Фронтенд

Код повторяет макет.

- **Маршруты** в `frontend/src/App.jsx`, оба ленивые: `/help` и `/help/:audience/:section/:slug`. Гейта `handle.can` нет — страница открыта каждому вошедшему. Ширина 944 в `layout/sheet-width.js`, запись `help` («Справка») в `util/sections.ts`.
- **`pages/Help/Index.jsx`** — оглавление. Заголовок «Справка»; у сотрудника `app/Segmented` «Сотрудникам | Клиентам» (выбор в адресе: `/help?for=client`), у клиента переключателя нет. `app/SearchBar`: фильтр на клиенте по `title` и `summary` без учёта регистра; при запросе — плоский список «статья — раздел», при пустом результате — пустое состояние с «Сбросить». Разделы — в две колонки CSS (`columns`) на десктопе, в одну на телефоне; у раздела линейка, название, число статей и все статьи строками. Справка без единой статьи (прямой переход по адресу): пустое состояние; клиенту — с действием «Новая заявка».
- **`pages/Help/Article.jsx`** — `app/Crumbs` с цепочкой «Справка › Раздел» (раздел ведёт на `/help#<раздел>`, с `?for=client` для клиентской части у сотрудника), заголовок, аннотация, «Обновлено …», кнопка `linkLabel` → `link`. У сотрудника на клиентской статье — плашка «Статья для клиентов» и «Скопировать ссылку». Слева `app/AnchorRail` «На этой странице» из заголовков `h2` — от трёх заголовков, только десктоп. Текст — `UI/MarkdownViewer` в обёртке `md-doc help-doc text-base leading-relaxed`. Внизу «Дальше в разделе» — остальные статьи раздела.
- **`UI/MarkdownViewer.jsx`** получает необязательный колбэк `onRendered(element)`: страница статьи проставляет в нём `id` заголовкам `h2` и собирает список для рейки. Остальные места использования не меняются.
- **`index.css`**, класс `help-doc`: мера 74ch для абзацев, списков, цитат и заголовков; таблицы, код и картинки во всю ширину; цитата — подложка с границей; картинка — граница и скругление.
- **`layout/Footer.jsx`** — ссылка «Справка» в служебной строке после версии; показывается при `hasHelp`.
- **Тёмная тема.** В макете линейки и границы блоков статьи ярче штатной `--border`, а текст статьи и строки оглавления на ступень тише `--foreground`: без этого в тёмной теме страница сливалась. В коде это два новых токена в `styles/tailwind.css` — `--rule` и `--foreground-soft`; в светлой теме они равны `--border` и `--foreground`. Используются только на страницах справки.

## Документация

- `docs/help.md` — как устроена справка и как добавить статью (на английском, без UI — как остальные модульные заметки).
- `docs/ux-ui-guide.md` — раздел «Справка»: целевой вид двух страниц; `docs/ux-ui-changelog.md` — запись о решении.
- Статей в поставке нет: `backend/help/` содержит только `sections.js`. Формат статьи с примером описан в `docs/help.md`.

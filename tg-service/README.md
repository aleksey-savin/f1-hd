# tg-service

Telegram-адаптер хелпдеска. Говорит с Telegram, ходит в бэкенд по HTTP и больше
никуда: своего подключения к базе приложения у него нет, копий моделей нет,
почтовых и облачных ключей нет.

Заменяет `telegram-bot/`, который был вторым сервером приложения — со своим
root-подключением к MongoDB, восемью расходящимися копиями моделей, счётчиком
номеров заявок, зеркалом ИИ-подбора категорий и отправкой всей исходящей почты.

## Что ему нужно

| Переменная | Обязательна | Зачем |
|---|---|---|
| `TG_TOKEN` | да | токен бота у BotFather |
| `TG_API_TOKEN` | да | общий секрет с бэкендом (заголовок `X-TG-Token`) |
| `BACKEND_URL` | да | `https://…` — база API; внутри compose `http://backend:8080` |
| `TG_DB_PATH` | нет | файл SQLite, по умолчанию `./data/tg-service.db` |
| `ADDRESS` | нет | адрес портала для кнопки «Подробнее» под заявкой |
| `NODE_ENV` | нет | `production` снимает предохранитель получателей |
| `DEV_TELEGRAM_CHAT_ID` | нет | куда уводить ВСЕ уведомления вне прода |
| `HEALTH_PORT` | нет | порт `/health`, по умолчанию 8081 |

Ни `MONGODB_*`, ни `S3_*`, ни `APP_ENC_KEY`, ни SMTP здесь не нужны и не читаются.

## Как запускается

Никакой сборки: Node исполняет `.ts` напрямую, стирая типы.

**Нужен Node 24+.** Не из-за типов — их 22.18 уже стирает сам, — а из-за
встроенного `node:sqlite`: до 23.4 он требует флага `--experimental-sqlite`.
Образ собран на `node:24-alpine`; на 22 сервис не поднимется, и `engines` в
`package.json` про это скажет.

```
pnpm install
pnpm typecheck     # гейт: должен быть зелёным
pnpm start         # node --watch src/main.ts
```

## Почему он может жить на другой машине

Обе связи исходящие — длинный опрос Telegram и HTTPS в бэкенд, — поэтому
входящих портов сервису не нужно вовсе (`/health` слушает только локально, для
healthcheck контейнера). Состояние — один файл SQLite: чем доставлено, что уже
нарисовано на табло и на каком шаге застрял диалог.

## Что где лежит

```
src/
  main.ts          сборка: конфиг → база → бот → работники → здоровье → выключение
  config.ts        разбор окружения, падает сразу и с именем переменной
  logger.ts        JSON в stdout; файлов не пишет — их читает docker logs
  api/             клиент бэкенда и формы его ответов
  store/           SQLite: доставленное, состояние табло, шаги диалога
  bot/             grammy: команды и отрисовка сообщений
  workers/         очередь уведомлений и табло статусов
  util/chatGuard   предохранитель получателей вне прода
```
